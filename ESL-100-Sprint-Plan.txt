"No cracks in the floor before you build higher."

Goal: Zero surprise crashes. Mobile doesn't die. TypeErrors don't embarrass.

─────────────────────────────────────────────────────────────
0A. AudioResumeGuard — Mobile First
─────────────────────────────────────────────────────────────
Problem: iOS Safari suspends AudioContext on page load. Any investor or
user opening ESL on an iPhone gets silence or a broken experience.

Fix: Wrap the app entry (index.tsx or App.tsx top level) with the existing
AudioResumeGuard component. On suspended AudioContext, show a one-tap
"Tap to Start Audio" overlay. Resume and proceed. Never let the audio
context die silently.

Test: iPhone 15 Pro Safari. iPad. Android Chrome. Must work on all three.

0B. TypeCheck Cleanup Pass
─────────────────────────────────────────────────────────────
Problem: Repo-wide typecheck backlog signals unfinished work to any
technical reviewer who opens the codebase.

Fix: Run `npx tsc --noEmit`. Fix the top 30 errors. Target: under 10
type errors in core src/ files (legacy test files can be excluded).
This is not about perfection — it is about the "unfinished house" impression.

─────────────────────────────────────────────────────────────
0C. Error Boundary Hardening
─────────────────────────────────────────────────────────────

Fix: Ensure every major panel (MultiStemWorkspace, AutoMasterPanel,
SettingsPanel, ExportPanel) is wrapped in the existing ErrorBoundary

─────────────────────────────────────────────────────────────

SPRINT 1 — WORKSPACE INTELLIGENCE (Weeks 1–2)
"Make the depth visible."
================================================================================

Goal: An engineer opens the workspace and immediately sees that this product
knows what it is doing.

─────────────────────────────────────────────────────────────
1A. Live Metering HUD
─────────────────────────────────────────────────────────────
Problem: The LUFS engine is complete. The AdvancedMeters component exists.
None of it is visible during playback in the workspace.

Fix:
  - Mount AdvancedMeters into MultiStemWorkspace as a persistent top bar
  - Show during playback: Integrated LUFS, Momentary LUFS, True Peak (dBTP),
    Stereo Width (0–100%), and a simple Crest Factor readout
  - Color code: green (target range), amber (approaching limit), red (over)
  - Add per-platform compliance badges that update in real time:
    Spotify ✓  Apple Music ✓  YouTube ✓  Tidal ✓

This is the single highest-impact change for professional credibility.

─────────────────────────────────────────────────────────────
1B. Smart Stem Labeling (Clean Rebuild)
─────────────────────────────────────────────────────────────
Problem: After stem separation, stems are labeled "vocals / drums / bass /
other" with no quality context. The previous attempt to add RMS analysis
caused a TDZ crash and was reverted.

Fix: Reimplement from scratch, no circular imports:
  - calculateApproxRmsDb(buffer): returns dB RMS for a stem
  - calculateStereoBias(buffer): returns -1.0 (L) to +1.0 (R) balance
  - buildSmartStemStateMap(stems): returns per-stem {label, rms, bias,
    confidenceBand, color}

Wire to stem cards in MultiStemWorkspace:
  - Each stem shows: name, RMS level badge, confidence indicator
  - Low-confidence stems show a warning: "Review — model was uncertain"

─────────────────────────────────────────────────────────────
1C. Engineer Advanced Mode — Real Differentiation
─────────────────────────────────────────────────────────────
Problem: The three onboarding profiles (First Song / Artist Fast Path /
Engineer Advanced) select a lane but change nothing in the actual interface.

Fix — gate these per profile:

  FIRST SONG:
    - Upload card
    - Single "Master It" button
    - Plain language result ("Your track is ready for Spotify")
    - No EQ, no meters, no routing visible

  ARTIST FAST PATH:
    - Genre selector
    - Per-stem volume sliders
    - One-click master + streaming compliance report
    - No hardware emulation visible

  ENGINEER ADVANCED:
    - Full metering HUD (Sprint 1A)
    - Per-stem EQ chains (ChannelEQPanel per stem)
    - SSL / Neve hardware emulation controls visible
    - Lookahead limiter threshold exposed
    - Raw LUFS numbers + streaming targets
    - Export quality controls (Sprint 2A)
    - Multiverse A/B comparison (Sprint 3B)

Implementation: Read `onboardingProfile` from context. Use conditional
rendering (not CSS visibility — actually not mounted for other profiles).

─────────────────────────────────────────────────────────────
1D. Workspace State Clarity
─────────────────────────────────────────────────────────────
Every state in the workspace needs an obvious visual signal:

  Uploading          → progress bar with file name and size
  Separating stems   → animated waveform with step label
  Processing master  → spinner with "Analyzing genre... Applying mastering..."
  Ready              → green "Release Ready" badge with LUFS readout
  Error              → red banner with one-tap retry

No ambiguous loading states. No invisible processing. The user always knows
exactly where they are in the pipeline.

Deliverable: Live metering visible. Stems labeled intelligently. Engineer
mode unlocks real tools. Every state has a clear visual signal.

SPRINT 2 — PROFESSIONAL LAYER (Weeks 2–3)
"Pass the engineer test."
================================================================================

Goal: A working audio engineer opens ESL and finds the controls they expect.

─────────────────────────────────────────────────────────────
2A. Export Control Surface
─────────────────────────────────────────────────────────────
The export panel needs:
  - Format selector: WAV 16-bit, WAV 24-bit, WAV 32-bit float, MP3 320kbps,
    MP3 V0, AIFF
  - Sample rate selector: 44.1kHz, 48kHz, 96kHz
  - Dithering toggle (for 16-bit exports)
  - Per-platform compliance check before download:
      Spotify: -14 LUFS ✓ / True peak -1.2dBTP ✓ → READY
      Apple Music: -16.1 LUFS — 0.1 dB over target → ADJUST?
  - "Download" button only enables when at least one target passes
  - "Download Anyway" override for Engineer Advanced profile

─────────────────────────────────────────────────────────────
2B. Hardware Emulation UI (Engineer Advanced only)
─────────────────────────────────────────────────────────────
The SSL 4000E, Neve 1073, and API 2500 implementations exist in the DSP
layer. Surface them:

  SSL 4000E Channel Strip Panel:
    Input trim, gate threshold/range/attack/release, 4-band EQ, VCA
    compressor threshold/ratio/attack/release. Channel assignment dropdown
    (which stem or bus it processes).

  Neve 1073 Preamp Panel:
    Input gain (stepped: -6 to +42 dB), 3-band stepped EQ (80Hz / 2.5kHz
    / 12kHz), output level. Per-stem or master bus insert.

  API 2500 Bus Compressor:
    Threshold, ratio, attack, release, knee, mix (parallel blend).
    Assigned to master bus by default.

Each hardware panel has an inline bypass switch and a gain reduction meter.

─────────────────────────────────────────────────────────────
2C. Reference Mix Comparison
─────────────────────────────────────────────────────────────
The ReferenceMixingPanel component exists. Wire it fully:
  - Upload a reference track
  - Extract reference LUFS, tonal balance, stereo width, dynamics
  - Show side-by-side: Your Master vs Reference
  - One-tap "Match Reference" applies gain and EQ to align targets
  - "How close am I?" score: 0–100 similarity to reference

─────────────────────────────────────────────────────────────
2D. Release Readiness Panel — Final QC Gate
─────────────────────────────────────────────────────────────
Full pre-release checklist (all auto-populated, user can override):
  [ ] Integrated LUFS within target range
  [ ] True peak below -1 dBTP
  [ ] No clipping on any stem
  [ ] Track metadata complete (title, artist, year)
  [ ] ISRC code (optional but flagged if missing)
  [ ] Format selected
  [ ] Streaming targets selected

Green checkmarks animate in as each criterion passes. When all pass,
a "Release Ready" seal animates in. This is a screenshot moment.

Deliverable: Engineer-grade export controls. Hardware emulation panels live.
Reference comparison working. Release Readiness Panel with the seal.

SPRINT 4 — PLATFORM COMPLETENESS (Weeks 4–6)
"No features that feel half-built."
================================================================================

─────────────────────────────────────────────────────────────
4A. Piano Roll + MIDI Export
─────────────────────────────────────────────────────────────
This is a differentiated feature no other browser mastering tool offers.

  - After stem separation, run NoteTranscriptionService on vocals and bass
  - Display result in PianoRollCanvas (already built)
  - Export as .mid file (standard MIDI, type 1, per-stem tracks)
  - Label: "Export MIDI" button in Engineer Advanced export panel
  - Use case: producer wants to replay the bassline in their DAW

─────────────────────────────────────────────────────────────
4B. Collaboration — Session Share
─────────────────────────────────────────────────────────────
  - "Share this session" generates a read-only link
  - Link recipient sees the workspace in a viewer mode:
      playback, metering, release readiness — no editing
  - Session owner can upgrade a viewer to "collaborator" (can comment)
  - Comments attach to a timestamp in the session
  - Uses Supabase Realtime for live playhead sync across viewers

This turns ESL into a client delivery tool, not just a production tool.
An engineer can master a track and share the session link with the artist
to approve before download. That is a workflow no LANDR or Ozone offers.

─────────────────────────────────────────────────────────────
4C. Undo / Redo in Workspace
─────────────────────────────────────────────────────────────
The HistoryManager service exists. Wire it to:
  - Every EQ change
  - Every stem volume/mute/solo change
  - Every master preset change
  - Hardware emulation parameter changes

Keyboard shortcut: Cmd+Z / Cmd+Shift+Z. Also expose in a HistoryTimeline
dropdown that shows the last 20 actions with timestamps.

─────────────────────────────────────────────────────────────
4D. Batch Processing (Render Queue)
─────────────────────────────────────────────────────────────
The RenderQueuePanel exists. Wire it:
  - Drag multiple tracks into the queue
  - Each gets auto-mastered with the same genre profile
  - Progress shown per track (queued → processing → done → download)
  - Download all as a zip
  - Use case: EP with 10 tracks. Master all 10 in one session.

─────────────────────────────────────────────────────────────
4E. WAM Plugin Rack (Engineer Advanced)
─────────────────────────────────────────────────────────────
The WAMPluginRack component exists. Wire it to accept Web Audio Module
plugins from the WAM community registry. Three slots on the master bus.
One slot per stem for insert effects.

This opens ESL to the entire WAM plugin ecosystem without building plugins
in-house. Instant pro credibility for engineers who know what WAM is.

Deliverable: Piano roll + MIDI export. Session sharing. Undo/redo live.
Batch queue working. WAM rack accepting plugins.

PHASE 2D: Material-Specific Finishing Strategies
─────────────────────────────────────────────────
Investment: 28k tokens
Timeline: 4 weeks

OBJECTIVE:
Different material needs different finishing approach.
Orchestral ≠ Jazz ≠ Classical ≠ Trap.

EXECUTION:

   - Train genre-specific submodels:
     * ORCHESTRAL: preserve transients, surgical EQ, pristine reverb, phase-aware sidechain
     * JAZZ: pocket-aware compression (preserve attack but smooth sustain), natural reverb, minimal distortion, high mono compatibility
     * CLASSICAL: zero artifacts, phase-coherent processing, transparent limiting, >98% mono
     * TRAP: aggressive parallel compression, saturation for character, locked LUFS, pristine exports
     * POP: balanced approach, clarity in vocals, locked bass, presence peak
     * R&B: smooth compression, subtle saturation, depth via reverb, natural spacing

2. Strategy selection (1 week)
   - On analysis: detect primary material type
   - Select appropriate strategy module
   - Apply genre-specific defaults + micro-moves

3. Finishing engine per material (1 week)
   - Orchestral finishing: NO parallel comp, surgical reverb tail, phase-metered sidechain
   - Jazz finishing: compress sustain only (attack preserved), natural room reverb, transient shaper for pocket
   - Classical finishing: transparent chain, NO saturation, NO aggressive compression, pristine limiting
   - Trap finishing: parallel comp ratio 8:1, saturation 18-22%, locked -14 LUFS, sidechain kick to bass

OUTCOME:
ESL detects "this is orchestral" and finishes it with orchestral principles, not one-size-fits-all.
