Operating Procedure

Standard Session SOP

Stage A: Ingest

  • Upload source or record into session
  • Confirm waveform loads cleanly
  • Do not batch edits before analysis completes

Stage B: Analyze

  • Confirm loudness/dynamics/balance are populated
  • Read plain-language summary first
  • Treat incomplete analysis as a blocking condition

Stage C: Propose

  • Use clear prompts: “aggressive vocals + slap delay”
  • Review Intelligence Feed proposals one by one
  • Skip unclear proposals

Stage D: Authorize

  • Hold proposal button to arm
  • Press Enter to confirm
  • Verify state hash/history update after execution

Stage E: Review

  • Use loudness-matched A/B only
  • Check active chain matches intent
  • Reject over-bright or over-limited outcomes

Stage F: Export

  • WAV for archive/delivery
  • MP3 for approval/share
  • Use queue when continuing active edits

Do not authorize what you cannot explain. The fastest safe workflow is selective approval, not blanket approval.

Governance + Determinism

ACC Enforcement and Timeline Safety

LOW Risk

Read-only and low-cost actions.

Often auto-approved under Co-Pilot/Full Autonomy.

MEDIUM Risk

State-mutating actions with moderate impact.

Typically review-gated except autonomy presets.

HIGH Risk

Destructive/heavy/export-level actions.

Explicit ACC approval required.

Deterministic Timeline Rules

  • Use history scrub as read-only preview first.
  • Use Restore explicitly before rewriting forward history.
  • Create branches before risky experimental edits.
  • Merge only after conflict review (OURS/THEIRS decision).
  • Treat state hash mismatches as incident-level issues.

Threat model in one line: tamper-evident history, replay-protected execution, cryptographically verified output.

Export Assurance

Provenance Verification Runbook

Required Deliverables per Export

  • .wav (or .mp3)
  • .manifest.json sidecar
  • Verified embedded provenance marker for WAV/MP3

Quick Marker Check (WAV)

Run from terminal at project root:

node -e "const fs=require('fs');const b=fs.readFileSync(process.argv[1]);console.log(b.includes(Buffer.from('ESL_PROVENANCE_REF'))?'marker-present':'marker-missing')" ./exported-track.wav

Expected output: marker-present

Manifest Fields to Validate

  • signature
  • manifestHash
  • signatureAlgorithm
  • Entries map to approved actions

No-Go Triggers

  • Missing sidecar manifest
  • Marker missing in WAV/MP3
  • ACC bypass behavior observed
  • Determinism gate failure in CI
Troubleshooting + Support

Operator Incident Response

Problem Likely Cause Corrective Action
No sound on iPhone/iPad Safari audio context suspended Tap resume/play once in-player
Proposal does not execute Not armed, ACC blocked, or policy denied Hold to arm, press Enter, inspect policy reason
Export failed or absent Render/signing path interrupted Re-run export and verify manifest endpoint availability
Unexpected session close Refresh/crash/navigation Restore session and verify hash continuity

Support Escalation Packet

  • Exact repro steps
  • Device / browser / OS version
  • Timestamp
  • Copy Debug Info payload
  • If export issue: WAV + manifest + marker-check result

Escalation quality rule: one complete packet is better than multiple partial reports.

Daily Operations

Checklists + Release Gate

Start of Day

  • Confirm version/build
  • Confirm output device path
  • Run ingest+analyze smoke pass

During Session

  • Branch before risky edits
  • Approve only understood proposals
  • A/B before any export sign-off

End of Day

  • Archive final audio + manifest
  • Document unresolved issues
  • Record deliverable status

Go / No-Go Criteria

  • GO: determinism gate passed, exports signed, marker present, A/B approved.
  • NO-GO: any ACC bypass signal, provenance mismatch, or determinism failure.

Final reference: Echo Sound Lab removes production friction, but operator taste and approval remain the final authority.
